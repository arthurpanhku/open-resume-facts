# resume-facts

*中文 · [English](README.en.md)*

> 用 Claude 或 Codex 管理自己的求职简历。
> 一句话：**事实源是唯一长期资产，简历是一次性产物。**

这是一个 **skill（方法本体）**，不是一个工具库。它不帮你写漂亮话，
它的全部设计目标是：**让 AI 写出来的简历，每一句都能在面试里被追问而不塌。**

## 为什么要这么做

直接让 AI 写简历，几乎必然出现这四类问题，而且写得越流畅越危险：

| AI 写的 | 实际是 | 面试后果 |
|---|---|---|
| "主导设计了 XX 平台" | 你是执行者之一 | 一问架构决策就露 |
| "全集团范围落地" | 还在试点 | 一问覆盖率就露 |
| "为客户交付 XX" | 内部职能，没有外部客户 | 一问客户名就露 |
| "9 年安全经验" | 总职业 9 年，入行安全 6 年 | 对不上时间线 |

这些不是"措辞问题"，是**事实问题**。平淡但真实的简历，比流畅但经不起追问的简历安全得多。

## 核心设计

1. **先采访，不要先写简历。** 建库第一步是把你的事实问清楚，一次问一组，
   不确定的一律标 `v: todo`，由你逐条核对——AI 不替你推断。
2. **事实源 `facts.yaml` 唯一。** 每条事实带核实状态（`user` / `cv` / `todo`）和 note
   （哪天、在哪次对话里确认的，哪些细节你没提供）。你改口时 note 追加更正记录，不覆盖旧说法。
3. **简历是一次性的。** 每个岗位一份 `CV_<公司>_<岗位>.md`，投完可删。
   投递过的保留（面试时要查当时递出去的版本），从未投递的推测稿直接删。
4. **约束机器可读。** `rules.yaml` + `lint.py` 检查日期、监管机构、证书、年限、
   内部口径数字、未确认事实，报文件名和行号。不依赖"我会小心"。

## 安装

### Claude Code

```bash
git clone https://github.com/arthurpanhku/open-resume-facts ~/.claude/skills/resume-facts
```

或只给当前项目用：

```bash
git clone https://github.com/arthurpanhku/open-resume-facts .claude/skills/resume-facts
```

之后在会话里说"帮我建个简历库"，或直接 `/resume-facts`。

> 注意：仓库名是 `open-resume-facts`，但**安装目录必须叫 `resume-facts`**（要和 `SKILL.md` 里 frontmatter 的 `name` 一致）。上面的 clone 命令已经处理了这一点。

### claude.ai

在 Settings → Capabilities → Skills 上传本仓库（含 `SKILL.md`）。

### Codex / 其他 agent CLI

把 `SKILL.md` 的内容作为项目规则文件即可：

```bash
cp SKILL.md AGENTS.md
```

或在第一条消息里整篇粘贴。方法本身与具体 agent 无关。

## 怎么用

**第一次**（约 30–60 分钟，大部分时间在回答问题）：

```
你：帮我建个简历库
AI：建好目录结构、git init 并提交，然后开始采访——
    先问你有没有现成简历或 LinkedIn 资料，再一组一组问经历、学历、证书、
    语言、项目、获奖、国籍与工作授权、可对外公开的数字。
```

采访完成前 **AI 不应该写任何简历**。

**日常投递**：

```
你：<粘贴 JD 全文>
AI：1. 读 facts.yaml 和 rules.yaml，再读 JD
    2. 把 JD 的职责和要求逐条列出
    3. 逐条对照你的事实，分三类：有证据的 / 没证据的 /
       "看起来像但其实不是"的（这类会单独点出来）
    4. 写简历（技术平台类岗位把项目放前面，传统岗位把工作经历放前面，目标两页）
    5. 跑 lint 到 0 错误，生成 PDF，检查页数
    6. 在 Applications/ 建投递记录，含待确认和风险点
    7. 单独列一节"本次新增的事实"，等你确认后才写进 facts.yaml
```

第 7 步是整套流程里最重要的人工环节，见下。

## 这套东西不保证什么

**`lint.py` 是模式匹配，不懂语义。**

- 它能抓：日期对不上、监管机构写错、facts 里没有的证书、禁用词、年限算错、
  内部精确数字外泄、标着 `v: todo` 的事实被写进简历
- **它抓不到：措辞夸大、细节超出事实范围、凭空出现的公司/职位/成果**

所以：

- 第 7 步"本次新增的事实"**不能省**，这是唯一能拦住语义级编造的环节。
- **lint 通过 ≠ 简历可以直接投。** 最终责任在你本人，签字前自己读一遍。

另外：这套方法不会让你的简历变得更"亮眼"。它会让简历变得**更保守、更具体**。
如果你要的是包装，这个 skill 帮不上。

## 仓库里有什么

```
README.md       # 本文件
README.en.md    # English version
SKILL.md        # 方法本体，给 Claude / Codex 读
LICENSE         # MIT
```

**仓库里刻意不含 `lint.py` 和 `build_cv.py`。**
因为检查规则是个人专属的——禁用哪条措辞、哪段经历只能提哪个监管机构、
证书白名单里有什么，都取决于你的事实。`SKILL.md` 给出了这两个脚本的完整规格，
由 AI 在你建库时按你的 facts 现写，比塞一份通用脚本更贴合。

你自己的 `facts.yaml` 属于个人隐私数据，**不要提交到公开仓库**。
